O que é

Ele opera o banco que você já tem.

Não provisiona, não hospeda, não guarda seus dados. Conecta no banco que já está de pé e entrega catálogo, consulta, grade, edição e exportação pelo navegador.

Nasceu de um problema chato: abrir um cliente pesado só para responder “quantas notas essa empresa emitiu em março?”. Está em produção diária num escritório contábil desde a v0.1.

Multi-engine

Sete motores, sete verdades.

Ícones do mesmo tamanho dizem que os bancos fazem o mesmo — e não fazem. Cada cartão traz o que existe, o que não existe, e onde mora a garantia.

PostgreSQL

completo

  • Árvore: conexão → banco → schema → tabela
  • Grade virtualizada, keyset, filtro e ordem
  • Editor SQL com autocomplete do catálogo
  • Escrita e DDL, com o comando na tela antes
  • Exportação CSV, TSV, JSON, NDJSON e SQL
  • Diagrama ERD gerado das chaves estrangeiras

Garantia em transação — BEGIN READ ONLY. Cobre DML e DDL, e o SQL do usuário não desliga.

MySQL

leitura

  • Árvore: conexão → banco → tabela
  • Catálogo: colunas, PK, índices e FKs
  • Grade com filtro, ordem e paginação
  • Consulta livre, com cancelamento
  • Exportação, DDL e edição de linha

Garantia em credencial — GRANT SELECT. Sem interruptor de escrita: não haveria o que ligar.

MariaDB

leitura

  • As mesmas capacidades de tela do MySQL
  • Driver próprio onde os dois divergem: limite de tempo, JSON e SEQUENCE
  • Exportação, DDL e edição de linha

Garantia em credencial. “MariaDB é MySQL com outra versão” foi medido, e é falso.

libSQL

leitura

  • Árvore, catálogo, grade e consulta — falado por HTTP
  • Selecionável no formulário; a credencial é o token JWT

Garantia em credencial — o claim "a":"ro" do JWT. O PRAGMA query_only não existe aqui.

SQLite

planejado · bloqueado

  • Bloqueado por medição, não por prazo
  • bun:sqlite é síncrono: uma consulta de 47 s deu zero tiques num temporizador de 10 ms

Garantia na abertura do handle (readonly: true) — o PRAGMA o usuário desliga.

MongoDB

planejado

  • Nada implementado
  • Precisa de outra vista: documento aninhado não cabe numa grade de colunas

Garantia em credencial — papel read. Um Mongo sem --auth não tem garantia nenhuma.

Redis

planejado

  • Nada implementado
  • Vista de chave/valor, seis tipos. Sem tabela não há grade, keyset nem ERD

Garantia em credencial — ACL +@read.

fonte: docs/multi-engine.md §1 e §3 · packages/shared/src/engine.puro.ts · docs/multi-engine-progresso.md. Medido contra PostgreSQL 16, MySQL 8.4.11 e MariaDB 11.8.9 reais.

Somente leitura

A regex sempre deixa um caso passar.

A proteção é o modo da transação, declarado no BEGIN — não um parser sobre o SQL que você digitou.

Adivinhar se a sua consulta escreve exige acertar em cima de CTEs, funções, DO blocks e identificadores citados. Sempre escapa um caso. No Postgres o DBee não tenta: o servidor recusa a escrita antes de o DBee opinar.

A parte incômoda é que isso só vale no Postgres. Nas outras a garantia mora em outro lugar — e o DBee mostra onde.

Onde mora a garantia de somente-leitura em cada engine, e o que escapa do mecanismo mais óbvio
Engine O óbvio, e o que escapa dele Onde a garantia mora
PostgreSQL 16 BEGIN READ ONLY — nada encontrado transação
MySQL 8.4 START TRANSACTION READ ONLY — escapam TRUNCATE e CREATE USER credencial
MariaDB 11 idem MySQL credencial
SQLite PRAGMA query_only — o usuário desliga com = OFF abertura do handle
libSQL PRAGMA query_only — não existe claim "a":"ro" do JWT
MongoDB 7 — papel read
Redis 7 — ACL +@read

E o que a proteção não é

Somente-leitura protege do acidente comum, não contém um papel privilegiado. Num superusuário, COPY … TO PROGRAM executa comando no host do banco de dentro de uma transação “somente leitura”. O DBee detecta e avisa ao testar a conexão — conter exigiria um parser de SQL, que é o que esta seção acabou de descartar.

Por que este

Seis decisões que dá para conferir.

Um container. Só.

Sem Redis de sessão, sem Postgres de metadado, sem fila. O estado local mora em bun:sqlite, num volume.

fonte: Dockerfile · deploy/docker-compose.yml

Auditoria de todo comando

Cada query vira uma linha em query_log: o SQL literal, quem executou, onde, o status, as linhas e a duração. Não é só escrita — é tudo.

fonte: migrations/001_initial.sql · queryLog.repo.ts

Papéis por conexão

Conta por pessoa, papel admin ou member, e permissão de escrita concedida por conexão. Escrever exige as duas coisas.

fonte: migrations/004_user_roles.sql

Feito para a tailnet

Sem porta pública por padrão: proxy interno, ou porta bindada no IP da tailnet. Roda como não-root e não monta o socket do Docker.

fonte: docs/operacao.md · Dockerfile

Exportação em stream

Cinco formatos, com a memória não crescendo com a tabela. Várias tabelas num .zip, do mesmo instante, com os filtros da tela.

fonte: README.md · CLAUDE.md regra 7. Só PostgreSQL.

A senha não sai daí

Senhas de conexão cifradas com AES-256-GCM. Credencial não é logada, não volta em resposta e não volta em erro.

fonte: README.md · CLAUDE.md regra 5

Instalar

Três passos, um container.

A imagem sai no GHCR e é amd64. Numa VM arm64 o container não sobe.

bash 
# 1. O segredo que cifra as senhas das conexões. Guarde num cofre.
openssl rand -hex 32

# 2. Suba o container (sem -p: veja o aviso sobre rede)
docker run -d --name dbee \
  -e APP_SECRET="<o hex do passo 1>" \
  -v dbee-data:/data \
  ghcr.io/joaoviitorsx/dbee:latest

# 3. Leia o token do primeiro acesso
docker exec dbee cat /data/setup-token
fonte: README.md · docs/operacao.md

  1. Abra pela rede interna

    Pelo IP da tailnet ou pelo proxy. O comando acima não publica porta, de propósito.

  2. Informe o token

    Escolha usuário e senha. O token some do volume nesse instante — nenhuma senha é gerada nem impressa em log.

  3. Cadastre a conexão

    Escolha o motor, preencha e teste. O teste avisa se o papel é privilegiado antes de você salvar.

Perder o APP_SECRET ou o volume /data = conexões perdidas. A chave que cifra as senhas vem do segredo e de um salt guardado no volume. Dois pontos únicos de falha, sem recuperação.

Suba o seu, e leia com calma.

As docs cobrem instalação, primeira conexão, papéis e o que cada motor faz hoje. Tudo o que a página afirma tem um arquivo atrás.
